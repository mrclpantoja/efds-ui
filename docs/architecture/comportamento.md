# Contrato de comportamento (JS/React)

O core é CSS puro. O que o CSS e a plataforma **não** entregam fica a cargo da camada React (`@eds-ui/react`), e — se um dia existir — do pacote de comportamento para quem usa só HTML (decisão em aberto). Este documento lista essas obrigações, levantadas nas auditorias de UX/WCAG 2.2 AA das Fases 2 a 4. O markup de referência de cada componente está em `apps/playground/src/demos/*.tsx`.

## Ações

| Componente | Obrigação                                                                                                                                                                                                                                                                                     |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Button     | Em `loading` (`aria-busy="true"`), ignorar clique **e** Enter/Espaço. Link desabilitado: sem `href` ou `preventDefault`, `tabIndex={-1}`.                                                                                                                                                     |
| Dropdown   | Padrão _disclosure_ (sem `role="menu"`). Sincronizar `aria-expanded` do gatilho pelo evento `toggle` do popover. Menu com `aria-labelledby` = id do gatilho. Itens ativos fecham o menu (`popovertargetaction="hide"`). Setas só quando houver JS de navegação; aí passa a ser `role="menu"`. |

## Formulários

- `data-required` em `.eds-label`/`.eds-legend` é só visual: o controle precisa de `required` ou `aria-required`.
- Erro: `aria-invalid="true"` + `aria-describedby` apontando para `.eds-error`; em grupos, descrever o controle, não o `fieldset` (evita leitura dupla).
- `indeterminate` do checkbox é propriedade DOM (definir via ref).
- Campos de dados **do usuário logado** com `autocomplete` adequado (WCAG 1.3.5). Em cadastro de terceiros (cliente, fornecedor, contato), `autocomplete="off"` para o navegador não preencher a entidade com os dados do operador.
- Validação no envio (`noValidate`): em erro, focar o resumo (`role="group"` + `aria-labelledby`, `tabIndex=-1`), com links que focam o campo sem alterar o hash; em sucesso, focar o alerta de sucesso. O resumo é o retrato do último envio e diz isso.

## Superfícies

| Componente     | Obrigação                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Modal / Drawer | Abrir com `showModal()` (foco preso, Esc e retorno de foco são nativos). Fechar pelo backdrop **só** se `pointerdown` e `click` ocorreram no próprio `<dialog>` (WCAG 2.5.2). Formulário: `autoFocus` no primeiro campo; informativo: foco no Fechar. Corpo rolável recebe `tabIndex=0` + `role="region"` + `aria-labelledby` **somente** quando rola de fato. Considerar confirmação ao fechar formulário alterado. No React, `onClose` é um pedido: Esc é interceptado (`cancel` + `preventDefault`) e o fechamento vem da prop `open`; em formulário com dados a perder, `closeOnBackdrop={false}`. |
| Card           | Card clicável usa link esticado (`.eds-card-link`), nunca o card como botão. Texto do card fica não selecionável — aceito.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## Navegação

| Componente                  | Obrigação                                                                                                                                                                                                                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tabs                        | Roving tabindex (`0` na ativa, `-1` nas demais), ←/→, Home/End. Aba indisponível com `aria-disabled="true"` (alcançável por setas, não ativa). Sem JS, não usar o padrão tablist. Foco e ativação são estados distintos (a aba indisponível recebe foco por seta, mas não é ativada); todos os painéis ficam montados, os inativos com `hidden`. |
| Sidebar (off-canvas mobile) | Popover não é modal: ao abrir, marcar `.eds-app-header` e `.eds-app-main` com `inert`; remover no `toggle` closed. Sincronizar `aria-expanded` do gatilho. Fechar (`hidePopover()`) ao navegar em SPA.                                                                                                                                           |
| Sidebar (colapsar)          | Botão com rótulo fixo, `aria-expanded` + `aria-controls`. Sem `title` no modo expandido. Só a sidebar do slot do shell (`.eds-app > .eds-sidebar`) é responsiva e ligada ao gatilho do menu; fora dele é estática. `.eds-sidebar-full` mantém a do shell expandida entre 768 e 1023px.                                                           |
| App shell                   | Um único `<main>` por página.                                                                                                                                                                                                                                                                                                                    |

## Feedback

| Componente         | Obrigação                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Toast              | Com um `dialog:modal` aberto, a região de toasts é renderizada **dentro** dele (portal); fora disso, na página. `danger`/`warning` não fecham sozinhos; demais: máx(5 s, ~1 s a cada 10 palavras), pausa em hover e foco. Esc fecha o toast focado. Ao fechar um toast com foco, devolver o foco a quem o disparou. `danger` anunciado como `alert`; demais `polite`. Toast nunca é o único canal de informação. Sem `title`, a severidade vai em prefixo oculto ("Sucesso:" etc.; `severityLabels` no provider). Enquanto houver toasts, o core reserva `scroll-padding-block-end` no scroller (WCAG 2.4.11). |
| Alert fechável     | Ao remover, mover o foco para um elemento lógico seguinte.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Spinner / Skeleton | Região `role="status"` montada vazia desde o início e preenchida ao entrar em loading (live region que nasce preenchida não é anunciada). Skeleton com `aria-hidden`; contêiner com `aria-busy="true"`.                                                                                                                                                                                                                                                                                                                                                                                                        |

## Telas e roteamento

- A cada mudança de rota (hash/SPA), atualizar `document.title` e mover o foco para o h1 da nova tela (`tabIndex=-1`), incluindo a volta à página inicial. Skip link funcional. Um único `<main>`.
- Indicadores (KPIs): o sentido bom/ruim nunca é só cor — ícone de direção (`aria-hidden`) + texto oculto "melhora"/"piora".
- Exclusão em massa: o modal informa a quantidade e que é irreversível; foco inicial em Cancelar; o foco volta a um elemento existente e habilitado.

## Limitações conhecidas

- **Tooltip da Sidebar compacta**: quando o trilho compacto rola (telas curtas na faixa 768–1023px), o rótulo flutuante fica deslocado na vertical pelo `scrollTop`. A correção limpa é CSS Anchor Positioning, que ainda não tem suporte no Firefox; reavaliar quando tiver.
- **Toast**: ao abrir/fechar um modal a região é remontada; o tempo restante é preservado no provider, mas a live region remonta e o leitor pode reanunciar os toasts visíveis. A região vem depois do conteúdo no DOM, então o Tab chega aos toasts por último; `role="alert"` do toast danger dentro da região polite pode gerar anúncio duplicado em alguns leitores — validar com leitor real antes de fixar no React.
- **Toast persistente** (warning/danger): o Esc só fecha com o foco no toast, e a região é uma das últimas paradas de Tab; o `scroll-padding` evita que cubra o foco, mas três ou mais toasts empilhados podem passar da folga reservada.
- **Tema em subárvore**: `data-theme` num elemento interno troca só os `--eds-accent-*`; os semânticos são resolvidos onde o modo é declarado. Para tematizar uma subárvore, declare `data-theme` **e** `data-mode` no mesmo elemento.
- **Modal/Drawer mantidos abertos pelo consumidor**: após o fechamento nativo, o diálogo reabre e devolve o foco ao último elemento focado dentro dele.
- **Table**: sem coluna fixa no MVP; ao rolar horizontalmente a coluna de identificação sai de vista (avaliar coluna sticky pós-MVP).
- **Popover da Sidebar**: com os irmãos em `inert`, a devolução nativa de foco falha; o JS devolve o foco ao botão de menu manualmente.
